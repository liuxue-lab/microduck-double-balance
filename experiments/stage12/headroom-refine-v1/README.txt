运行流程
1. --install-code：从单文件入口取出增量 bundle，验证基线，导入临时远端引用并 fast-forward。
   不自动推送；若有本机未提交修改或分歧，则保留并停止，不覆盖用户文件。
2. 用户执行原有 git push origin double-balance。
3. --train：首次在终端粘贴本阶段当前 5090 SSH 指令；复用一次认证，不读取或保存密码。
   云端先取已提交的代码，核对已有模型和源文件，不安装依赖、不重跑旧诊断。
4. 后台依次运行 5 次 smoke（含 ONNX 导出检查）、最多 250 次正式 PPO、2 回合候选评估。
   两回合全通过就提前停学并做 4 回合留出；否则最多再训 250 次并评估两回合。
   仍无合格候选则结束；留出失败也结束，不利用留出种子继续调参。
5. 本机入口监控到终态后自动通过 Git SSH 回传必要模型、账本、指标、失败结果、全部新评估 trace。
   所有文件本机 SHA256 校验通过后，立即提示手动关云 GPU；脚本不会操作实例电源。

所有“尝试”在第一条物理 rollout 之前写入持久预算；失败/中断不退款。
重复 --train 读取同一任务，不新开预算；--resume 只允许检查点与预算一致、无未完成尝试/评估、

常用入口
--status：只读状态，保存 JSON；--watch：只读监控；--collect：只读收集报告。
--stop：明确停止本轮作业，不关闭实例；--resume：仅符合上述条件时续同一预算。
--return：只重试云端资料打包/push与本机下载；--download：已有云推送回执时，仅走 Git SSH 下载，
无需云 GPU 在线；这两个操作均不启动训练。
监控 Ctrl+C 只退出本机监控，后台作业继续。之后用 --watch，终态后用 --return。

若出现 SSH/推送/SHA/环境错误，保留打印的 JSON 和日志再审查，不用旧程序重启训练。
密码认证只在明确建立/重建 SSH 会话时发生；若会话已断，状态命令重建一次，不在后台反复弹密码。
